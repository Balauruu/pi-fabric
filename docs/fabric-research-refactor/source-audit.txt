## 1. Execution trace and consequential findings

### Validation → preflight → dispatch

1. `π.program` is JSON-parsed and closed against an allowlist. Requirements and streams are separately closed, normalized, checked for uniqueness, and checked for ownership. The later top-level object check duplicates the earlier `closed()` rejection. `π.task` is interpolated without equivalent validation. **P:6–153, 286**.
2. Preflight lists only the first **200** extension actions, then intersects four hardcoded retrieval names. An explicitly requested missing tool blocks **all streams**, even if another available tool could serve some streams. Listing, policy reads, and malformed-manifest failures are outside a protective outer catch. **P:154–182, 342–378**.
3. Policy is extracted using exact Markdown headings. A missing Browser rule aborts the program; a missing current-field heading or invalid artifact directory blocks that stream. Artifact input checks are lexical, not freshness, existence, symlink-containment, or output-path checks. **P:170–182, 274–281**.
4. Native `agents.run` receives the assignment and report schema. There is no local report-schema validator. Required source classes and evidence standards become prompt text, not verified conditions. **P:282–302, 325–334**.

### Schema → candidate filter → evidence loss

Three distinct mechanisms matter:

- **Schema rejection:** oversized or otherwise invalid structured delivery is a native failure. The workflow keeps selected receipt fields and a diagnostic, **not `result.text` or the rejected report body**. Recovery may remain possible through native logs, but it is absent from this returned outcome. **P:294–323**.
- **Candidate exclusion:** successful reports keep their entire `report`. Rows with incomplete provenance or any foreign requirement ID are excluded only from candidate accounting. They are **not deleted**. **P:325–334**.
- **Prompt-induced omission:** retrieval stopping instructions can prevent evidence from being collected. This is advisory behavior, not enforced or measured by this program. **P:290, 315–316**.

The provenance gate requires only truthy `sourceType`, `locator`, `retrievedAtUTC`, `method`, and `origin`. It does **not** validate timestamp semantics, source authenticity, exact-passage entailment, independence, source-class compliance, or temporal fit. Whitespace satisfies the schema’s string minimum and remains truthy. **P:199–202, 230–244**.

Consequently:

- Missing retrieval time can demote otherwise useful evidence.
- A fabricated-looking but schema-valid provenance bundle can qualify.
- A row tagged with both an assigned and foreign ID loses eligibility for **all** its IDs.
- `incompleteEvidenceRows` also includes foreign-ID rows, so its name conflates different problems. **P:327–331**.

**Decision:** remove automatic candidate eligibility. Preserve evidence and unresolved verification questions; Main determines support claim by claim.

### Retry and failure behavior

Failure classification uses substring precedence:

`budget` → `schema/validation` → `timeout` → `tool` → generic agent failure.

Classification operates on a diagnostic already truncated to 500 characters. Native terminal status survives separately when a receipt exists. **P:12, 188–197, 304–323, 335–339**.

Retry is:

- opt-in only;
- after the entire initial fan-out;
- one fresh attempt;
- for the first eligible missing required item in requirement iteration order;
- only when exactly one stream owns it;
- excluded for `completed-usable`, `failed-budget`, and `blocked-preflight`. **P:380–403**.

Important blind spots:

- A usable stream missing another uniquely owned required item **cannot retry**.
- Multiple failed owners of one required item **cannot retry**.
- Coordinator-owned requirements are treated as covered for retry selection even while their final status remains `pending-coordinator`.
- Retry assignment includes prior status and diagnostic/gaps, not prior evidence or an explicit computed missing-requirement subset. **P:292, 384–420**.

**Decision:** remove the universal retry algorithm. Keep explicit, task-specific recovery within user/native attempt budgets, without rerunning successful work.

### Concurrency and results barrier

`await parallel(...)` precedes retry, accounting, and return. This is a real initial-results barrier at the call-site level. Returned worker failures and thrown dispatch errors normally become outcomes, preserving siblings. **P:267–341, 380–404**.

It is not an unconditional failure barrier:

- The initial `workflow.item(...running)` is outside `try`.
- Failure-reporting `workflow.item` calls can themselves throw.
- Later phases/events can reject before the aggregate return.
- The program does not open or verify retained artifact bodies before returning. That obligation exists only in guidance. **P:269, 277, 322–338, 399–404, 435–438**; `skills/fabric-research/SKILL.md:135–136`.

**Decision:** retain all-settled-style result collection and explicit artifact consumption, not this whole orchestration wrapper.

### Completion and telemetry

`success` means **every stream supplied at least one candidate row**, not that all required items have evidence. `completed-no-usable-evidence` is structurally valid and excluded from `failures`; therefore zero usable streams can produce overall `failed` with an empty failure list. **P:405–434**.

Telemetry has useful honesty, but significant qualifications:

- Per-child usage comes from native receipts, not text.
- Missing usage fields propagate `"unavailable"`.
- One unreceipted attempt makes aggregate child usage and tool calls wholly unavailable, although measured sibling receipts remain.
- Dispatch count is inferred from outcome attempt numbers, not incremented at `agents.run`.
- `serviceTimeMs` excludes initial item reporting and queue wait; `durationMs` measures program execution, not necessarily the earlier supplied research start.
- `tokenBudgetObservation` explicitly does **not** apply to raw `agents.run`.
- Provider/search costs, parent usage, cancellation, and retrieval-step compliance are not measured. **P:4–5, 38–41, 183–187, 270–316, 427–483**.

**Decision:** retain raw native receipts and measured/unknown distinctions. Remove redundant projections and capability declarations. Report known subtotals as incomplete rather than erasing them or implying a complete total.
