01 · Intent

Goal and Scope

Goal

Allow callers to set LOG_LEVEL_ALIAS when LOG_LEVEL is absent or empty, while retaining LOG_LEVEL as the canonical, higher-priority key and retaining info as the final fallback.

Out of scope

  • Log-level validation or normalization.
  • Changes to logging output, transports, or startup behavior.
  • A generalized environment-variable alias framework.
  • Deprecating or renaming LOG_LEVEL.

02 · Evidence

Current State

src/config.js exports a synchronous logLevel(env = process.env) function. It returns the truthy value of env.LOG_LEVEL, otherwise the literal info. This preserves dependency injection for tests and uses JavaScript truthiness for empty values.

function logLevel(env = process.env) {
  return env.LOG_LEVEL || 'info';
}

test/config.test.js currently proves only an explicit LOG_LEVEL value and the empty-object fallback. The project uses Node’s built-in test runner through npm test; there are no runtime dependencies.

Constraint: compatibility means a truthy LOG_LEVEL must always win, including when both names are supplied.

03 · Decision

Proposed Design

Extend the existing truthy fallback chain in place. This is the smallest change and deliberately keeps the resolver’s current treatment of missing, undefined, null, and empty-string values.

function logLevel(env = process.env) {
  return env.LOG_LEVEL || env.LOG_LEVEL_ALIAS || 'info';
}
