# Update Plan

Completion means a surgical current-only change, appended lifecycle history, stable semantic IDs, and passing validation.

1. Resolve the target and run `node "$VALIDATOR" "$PLAN_FILE"`. Reject legacy, unmarked, mixed-marker, and non-PlanF3 inputs; no compatibility or migration flow exists.
2. Scope only the semantic records, execution observations, presentation sources, or mappings whose meaning changes. Preserve all unrelated content and never renumber existing `REQ/DEC/EVD/PHS/UNT/CHK/VAL` IDs.
3. Preserve settled decision intent. To change a decision, amend the existing record: update the single live choice/status as appropriate and append dated supersession/revisit history identifying the prior choice, reason, evidence, and provenance. Never stack contradictory live rules or silently rewrite historical intent.
4. Keep evidence load-bearing and linked. Keep source and illustrative code in the shared code snippet figure. When source or revision changes, revalidate source-variant line content, exact numbered line spans, and whole-file SHA-256. Keep illustrative variants visibly labelled and guard-free; update or remove them when they drift from authoritative unit intent. Update, relink, or deliberately remove stale evidence rather than leaving it decorative.
5. After any unit File Impact or ownership change, keep each authority a concrete Before/After delta, then regenerate the actionable File impact index and every File Map actionable path set from unique current unit-local paths, including owner backlinks and validation relations. Knowledge resources remain resources, not File Impact.
6. After dependency or ownership edits, re-derive deterministic waves/modes, visible Execution order fields, the exact collision-free normalized SVG source restricted to `flowchart TD` plus one simple `-->` edge per nonempty line for split/convergence/terminal closeout, and the exact phase-grouped/unit-wave-banded fallback. Keep phase owner/detail lanes unmistakable. Keep the single global Key metrics overview after the hero, update its scorecards without duplicating authority, and repair report KPIs, comparisons, review links, Decision Log wrappers, snippet headers, re-entry, ordinals, symbols/type labels/permalinks, observability inventory, and phase/unit ledgers. Recompute readiness separately from execution: blocking unresolved questions mean `blocked`; intentional incompleteness means `draft`; complete awaiting review means `review-ready`; explicit approval means `approved`.
7. Preserve immutable `created`; append timestamp, available agent/session, and one concrete amendment containing scope and rationale. Lifecycle and amendment histories are append-only.
8. Run validation and report exact changed records, preserved IDs, evidence/snippet treatment, projection changes, readiness basis, and deterministic output. Route explicit deepen requests through `workflows/deepen-plan.md`.
