# Telemetry

Use this reference to retain and aggregate runtime, usage, tool, latency, and cost evidence without losing provider semantics. The telemetry schema owns machine field names. Preserve raw payloads before deriving normalized views.

## Identity layers

Record identity at every measured parent, nested child, and model-grader node.

| Layer | Meaning | Typical evidence |
| --- | --- | --- |
| Requested | What the sealed condition asked Fabric to run | Schedule, condition, and exact `agents.run` request |
| Resolved | What Fabric selected or returned | `runner`, `model`, `thinking`, `transport`, `cwd`, agent ID, and optional `runnerSessionId` from the full result |
| Observed | What the provider/runtime independently reported | Provider response metadata, session transcript, run log, process receipt, or versioned native envelope |

Do not collapse these layers. A match between requested and Fabric-resolved values proves selector resolution, not independent provider attribution. `FabricAgentResult.model` may be missing or derived by Fabric. Store observed provider/model/revision when exposed; otherwise use `unknown` and limit comparability claims. Package defaults and model catalogs are not observed identity.

Bind every node to `benchmark_id`, execution revision, attempt or grader ID, Fabric agent ID, parent node ID when nested, and the source artifact digest. Reused display names never establish identity.

## Preserve provider-native records

For each provider-bearing event or result:

1. retain the authorized native payload or an immutable pointer;
2. record provider, API/runtime schema name and version when known, source path, capture time, and content digest;
3. project only fields whose semantics are documented for that source;
4. retain fields that have no cross-provider equivalent instead of dropping them;
5. mark absent, redacted, unsupported, and unobserved values distinctly when the schema permits.

Pi Fabric 0.77.0 exposes normalized result usage as `input`, `output`, `cacheRead`, `cacheWrite`, and `cost` (installed contract evidence PF2 and PF7 in [architecture](architecture.md#installed-contract-evidence)). Preserve those exact values with source `FabricAgentResult.usage`. They are not a universal provider schema. Also retain provider-native input, output, reasoning, cache read/hit, cache creation/write and duration/tier fields when available. Do not infer reasoning tokens, cache categories, or billing semantics from names alone.

A local cost estimate must be separate from provider-reported cost and include currency, rate-card source/version/date, rounding rule, and the native quantities used. Never replace a provider total with an estimate or combine currencies silently. A universal normalized cost/token formula is not required.

## Direct and subtree usage

Treat each model-bearing node as an accounting entity. Each usage record declares one category:

- **direct:** usage generated by that node only;
- **inclusive:** a runtime total known to include one or more descendants;
- **unknown-scope:** the source does not establish whether descendants are included.

Never add an inclusive or unknown-scope parent to child usage. Compute a subtree view only from unique direct records:

```text
subtree(node) = direct(node) + sum(direct(descendant))
```

This equation is valid only when every included record has one unique owner and direct semantics have been verified for that runner/version. Otherwise report the available direct, inclusive, and unknown-scope records side by side and leave the subtree field unknown.

For every descendant, require exactly one parent ownership edge and one attempt or grader root. Reject duplicate agent IDs within the same execution lineage, cycles, orphan children, crossed session IDs, or the same native payload digest claimed by two nodes. A model grader belongs to the grader traffic root, not the measured attempt subtree.

Aggregate each native category independently. Do not manufacture a `total_tokens` value by adding a provider's reasoning output when it is already included in output, or by adding cache reads when the provider's total already includes them. If a provider publishes its own total, retain that total and its definition.

## Tool activity

Separate these facts:

1. tool definitions advertised to the node;
2. model-issued tool calls;
3. tool results, errors, durations, and retries;
4. coordinator or harness calls made outside the measured node.

`FabricAgentResult.toolCalls` is a useful direct scalar when present (PF2 in [architecture](architecture.md#installed-contract-evidence)). Preserve it, then retain structured session/run tool events when available for names, call IDs, arguments or redacted argument digests, results, errors, and timing. Configuration or prompt mention does not prove use. Count a retried call as another call and also connect it to the prior call when the runtime provides identity.

For nested agents, attribute the dispatch tool call to the caller and the nested child's own tools to that child. Do not count one nested call in both parent direct and child direct totals. Declare transcript or log blind spots rather than proving scope compliance from path-string searches.

## Latency boundaries

Use coordinator monotonic time for intervals measured within one process. Retain wall-clock timestamps for audit joins, with clock source and precision, but do not order cross-process events by timestamp alone.

Report these boundaries separately when observed:

- assignment publication to call issue;
- call issue to returned terminal result;
- Fabric/provider startup, from runtime-reported `startedAt` or native evidence;
- queue, setup, model, tool, retry, and cleanup intervals;
- attempt service time and end-to-end assigned time;
- grader service time;
- benchmark makespan from first scored call issue to last scored terminal publication.

`startedAt` and `finishedAt` returned by Fabric are runtime metadata, not coordinator monotonic measurements. Do not subtract clocks from different sources unless synchronization and units were verified. Missing sub-intervals do not justify allocating total latency proportionally.

Report makespan with the proven maximum active agent count, configured ceiling, wave count, worker-slot utilization, service tier, throttling/rate-limit events, and whether grader traffic overlapped. Maximum concurrency means the greatest concurrency observed runnable for the sealed condition and service regime, not the semaphore setting or number of ready rows.

## Cost and denominator rules

Retain separate totals for:

- measured attempt parents;
- measured nested descendants;
- model graders;
- non-scoring canaries;
- deterministic/local processing;
- tool, sandbox, network, and human review when measurable.

Primary efficiency summaries include every assigned attempt, including timeout, malformed output, provider error, and other failure classes according to the frozen invalidation policy. Report at least cost per assigned task and total cost per accepted task. Conditional successful-attempt cost is diagnostic and must be labeled as such.

Keep denominators for scheduled, assigned, started, treatment-verified, mechanism-exposed, terminal, grader-complete, and accepted records. Do not let telemetry availability create a filtered quality denominator. A missing usage payload remains an assigned result with unknown usage.

Workflow `tokenBudget`, recursive USD budget, and per-child token guards are observational controls that may overshoot before the runtime observes and stops a child (PF3-PF5 and PF7 in [architecture](architecture.md#installed-contract-evidence)). Record configured guard, observed usage, overshoot, and stop status. Call a ceiling hard only when the provider/runtime can prove enforcement before additional consumption. Use provider-side controls when a hard spend or token boundary is required.

## Missing and contradictory data

Never coerce missing values to zero. Zero means the source explicitly reported zero. Preserve:

- `unknown` when no decisive source exists;
- the native null/absence when it has documented meaning;
- conflicting values as separate source-qualified observations;
- a reconciliation finding when identifiers or totals disagree.

Choose a value for analysis only by a frozen precedence rule. Record both the selected projection and all contradictory native evidence. Runtime or serialization repairs may recover fields from contemporaneous immutable evidence, but may not ask a model, query new mutable evidence, or rewrite a raw payload.

## Aggregation gate

Telemetry aggregation passes only when:

- every telemetry row resolves to one scheduled attempt or grader and one unique node owner;
- requested, resolved, and observed identity layers remain distinguishable;
- all native payloads and projections identify their source and version;
- parent direct, parent inclusive, nested direct, and subtree views cannot double count;
- cache and reasoning fields preserve provider semantics;
- tool calls and model usage do not cross attempt/grader or parent/child ownership;
- unknown values survive aggregation and remain visible in denominators;
- sums reproduce their included source rows exactly;
- grader and canary traffic remain separate from scored attempt totals.

Only aggregate a metric across providers when the report states the common definition and verifies that every source satisfies it. Otherwise report provider-native distributions separately.
