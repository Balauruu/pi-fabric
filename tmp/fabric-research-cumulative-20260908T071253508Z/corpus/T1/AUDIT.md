# T1 source audit

## Audit boundary
This is a source-audited fact ledger, not an expected answer. “Measured” is a result in a cited source. “Proposed control” is an operational test/control warranted by the evidence but not measured as a universal prescription.

## Controls derived for local evaluation

| Control | Status | Evidence connection and limit |
|---|---|---|
| Pair a direct baseline with CoT on the same multi-step and one-step strata, fixed model/version, decoding, exemplar set/order, output parser, and token/latency budget. | Proposed control | F1–F2 show conditional effects and prompt sensitivity boundaries, not an SLO. |
| For ToT, record success, tree breadth/depth, generations/evaluations, completion tokens, wall time, and total price. Compare at matched or disclosed compute. | Proposed control | F3–F5 report result and completion-token/cost burden, but not a general cost threshold. |
| For long contexts, move the same answer-bearing item across beginning, middle, and end at production lengths. Test query repetition separately by task type. | Proposed control | F6–F7 are controlled position/query interventions; F7 explicitly does not transfer its key-value lift to multi-document QA. |
| For tool loops, cap steps, log retrieval result and final answer separately, and verify final state/postcondition. | Proposed control | F8’s 7/5 fallback caps and F9’s search/reasoning failures motivate the control. The study did not measure a generic postcondition checker. |
| Attempt repair only after a trustworthy compiler, test, API, or human review produces actionable feedback. Record base success, repair success, feedback source, retries, and false passes. | Proposed control | F10 isolates feedback quality. It is not a proof that every external validator is reliable. |
