# Tree of Thoughts adoption evidence note

## Assigned question and boundary

**Question:** Should a production reasoning workflow adopt Tree of Thoughts (ToT) rather than direct/IO or chain-of-thought (CoT) prompting, based on the original study’s quality, compute, and transfer evidence?

**Bounded answer:** **Do not make a default production switch.** The original paper supports a targeted, locally validated ToT option for tasks that demonstrably require branching search and where CoT fails. It does not establish a general production advantage. Its strongest Game of 24 result used task-specific decomposition, proposal, self-evaluation, BFS, and substantially higher cost. Its Creative Writing result is smaller, relies partly on the same model as judge, and iterative refinement beat ToT on the paper’s automated metric.

**Scope:** only the original [arXiv v2 HTML paper](https://arxiv.org/html/2305.10601v2), including its Appendix B cost analysis, dated 3 December 2023. Experiments were conducted 5–16 May 2023 with Chat Completion GPT-4 at temperature 0.7. No outside studies used.

## Measured evidence

### F1. Game of 24: a large but narrow improvement

The test set was 100 relatively hard games, indices 901–1,000 of 1,362 games scraped from 4nums.com. Success required a valid equation equaling 24 and using each input number exactly once. ([§4.1](https://arxiv.org/html/2305.10601v2#S4.SS1), [Table 2](https://arxiv.org/html/2305.10601v2#S4.F3))

| Method and condition | Success |
|---|---:|
| IO prompt, 5 in-context examples | 7.3% |
| CoT prompt, 3 intermediate equations | 4.0% |
| CoT self-consistency, majority of 100 samples | 9.0% |
| ToT BFS, breadth `b=1` | 45% |
| ToT BFS, breadth `b=5` | **74%** |
| IO + refine, up to 10 iterations, with equation-correctness feedback | 27% |
| IO, oracle best-of-100 | 33% |
| CoT, oracle best-of-100 | 49% |

The 74% result is not simply “ask for several answers.” ToT decomposed the puzzle into three intermediate equations, used a task-specific **propose** prompt, retained the best five states at each BFS step, and had GPT-4 classify candidate states as `sure/maybe/impossible`, sampled **three times per candidate**. ([§4.1](https://arxiv.org/html/2305.10601v2#S4.SS1))

The cost-matched contrast is informative but not fully matched: **ToT’s 74% vs CoT best-of-100’s 49%** used 5.5k vs 6.7k generated tokens per case, respectively. This supports the claim that, on this constrained search problem and implementation, intermediate branching plus evaluation outperformed independent whole-chain sampling at roughly comparable completion-token scale. It does **not** show a generic ToT advantage. ([Appendix B.3, Table 7](https://arxiv.org/html/2305.10601v2#A2.SS3))

### F2. Creative Writing: improvement, but an important counter-result

Task: 100 inputs of four random sentences. Output: a coherent four-paragraph passage whose paragraphs end in those exact sentences. There was no ground-truth target. ([§4.2](https://arxiv.org/html/2305.10601v2#S4.SS2))

| Method | GPT-4 coherence score, 1–10 |
|---|---:|
| Zero-shot IO | 6.19 |
| Zero-shot CoT, brief plan then passage | 6.93 |
| ToT | 7.56 |
| IO + iterative refine | **7.67** |
| ToT + iterative refine | 7.91 |

For ToT, GPT-4 generated five plans, sampled five votes to choose one, generated five passages conditioned on it, and again sampled five votes. Breadth was one after each vote. ([§4.2](https://arxiv.org/html/2305.10601v2#S4.SS2))

Human blind pairwise comparison of ToT versus CoT over 100 input pairs found: ToT preferred **41**, CoT preferred **21**, similarly coherent **38**. The automatic GPT-4 judge used five samples per output, with average within-output standard deviation about 0.56. ([§4.2](https://arxiv.org/html/2305.10601v2#S4.SS2))

**Qualification:** ToT improved over the direct and CoT baselines, but iterative refinement of IO alone scored higher than ToT (7.67 vs 7.56). Thus this experiment does not support replacing refinement or treating explicit tree search as the uniquely preferred production control.

### F3. Original token and dollar accounting

The paper labels columns **“Generate/Prompt tokens”**, so the first quantity is completion/generated tokens and the second prompt tokens. These are historical per-case figures from the original GPT-4 setup, not current pricing forecasts.

| Task / method | Generated / prompt tokens per case | Historical cost per case | Outcome |
|---|---:|---:|---:|
| Game24, IO best-of-100 | 1.8k / 1.0k | $0.13 | 33% |
| Game24, CoT best-of-100 | 6.7k / 2.2k | $0.47 | 49% |
| Game24, ToT | 5.5k / 1.4k | $0.74 | 74% |
| Creative Writing, IO | 0.9k / 0.4k | $0.06 | 6.19 |
| Creative Writing, CoT | 0.9k / 0.4k | $0.07 | 6.93 |
| Creative Writing, ToT | 4.0k / 2.9k | $0.32 | 7.56 |

Sources: [Game24 Table 7](https://arxiv.org/html/2305.10601v2#A2.T7), [Creative Writing Table 8](https://arxiv.org/html/2305.10601v2#A2.T8).

The paper says the two main 100-case ToT experiments cost approximately **$106**: `0.74 × 100 + 0.32 × 100`. It estimates its crossword DFS experiments were also within $100. It generalizes only that ToT may require **5–100×** as many generated tokens as CoT, depending on prompts and search algorithm. ([Appendix B.3](https://arxiv.org/html/2305.10601v2#A2.SS3))

**Source fidelity note:** Table 8’s header and rows clearly identify Creative Writing, but its caption says “Cost analysis on Game of 24.” This is an original-paper caption error. The numerical rows are reported above as Creative Writing, not silently relabeled as Game24.

## Methods and applicability

### F4. What was actually compared

- **IO:** direct answer generation. Game24 used five-shot IO. Creative Writing used zero-shot IO.
- **CoT:** Game24 added three intermediate-equation demonstrations. Creative Writing asked for a brief plan before writing.
- **CoT-SC:** only reported for Game24, 100 independent CoT samples with majority output.
- **Best-of-100:** an **oracle** metric for Game24. It computes whether any of 100 samples succeeds, not a deployable selection mechanism without a verifier.
- **Refinement:** Game24 used correctness feedback, effectively a ground-truth verifier. Creative Writing used model-directed refinement.
- **ToT:** a family, not one fixed algorithm. This paper instantiates it through task-specific thought granularity, generator prompts, LLM state evaluation/voting, and BFS. Game24 uses three equation steps and `b=5`. Creative Writing uses plan selection then passage selection, five candidates and five votes per stage. ([§3](https://arxiv.org/html/2305.10601v2#S3), [§4](https://arxiv.org/html/2305.10601v2#S4))

## Transfer limits and counterevidence

### F5. The authors’ own limitations matter for adoption

1. **Narrow constructed tasks.** The main evidence is three relatively simple tasks designed to challenge GPT-4, not real production workflows. The paper explicitly says ToT may be unnecessary for many tasks GPT-4 already excels at. ([§6](https://arxiv.org/html/2305.10601v2#S6))
2. **Model and era dependence.** All principal comparisons use May 2023 GPT-4. With GPT-3.5-turbo, Game24 ToT falls from 74% to 19%, despite still exceeding GPT-3.5 IO 6% and CoT 3%. ([Appendix B.2](https://arxiv.org/html/2305.10601v2#A2.SS2))
3. **Generation quality was the Game24 bottleneck.** GPT-4 generation with GPT-3.5 evaluation scored 64%, while GPT-3.5 generation with GPT-4 evaluation scored 31%. This indicates a local dependence on generation capability, not proof that self-evaluation/search transfers across model pairs. ([Appendix B.2](https://arxiv.org/html/2305.10601v2#A2.SS2))
4. **Evaluation quality is unvalidated for open-ended work.** Creative Writing’s primary numeric metric is GPT-4 judging GPT-4 outputs. Human comparison is directional but not a scalar quality estimate, and uses a subset of authors.
5. **Unequal selection power.** The Game24 “best-of-100” comparator is oracle-selected, while ToT has an LLM evaluator. Conversely, ToT’s custom evaluator and proposal prompt encode substantial task-specific design effort. Neither is a simple out-of-the-box prompting comparison.
6. **Cost and latency grow with branch and vote count.** The original paper recommends configuring beam size and vote count against resources and says ToT can require 5–100× more completion tokens than CoT. It provides no production latency, tail-latency, reliability, or safety measurements. ([Appendix B.3](https://arxiv.org/html/2305.10601v2#A2.SS3))

## Adoption boundary

**Measured conclusion:** adopt ToT only as a candidate escalation path when all three are true:

1. The task has meaningful, externally checkable intermediate states or a credible evaluator.
2. Direct and CoT workflows demonstrably fail on representative cases because an early commitment blocks recovery.
3. The additional token, latency, and engineering cost has measurable business value.

**Proposed control:** retain direct/CoT as default. Route only eligible difficult cases to bounded ToT. Do not use the paper’s historical dollar figures as current budget estimates.

## Proposed matched local evaluation

This is a proposed evaluation, not a result of the paper.

1. **Dataset:** freeze a representative, held-out production task set. Stratify by difficulty and by availability of deterministic verification, human rubric, or outcome signal.
2. **Arms, same model snapshot and temperature:** direct IO, CoT, CoT self-consistency, iterative refinement, and ToT. Use the same system prompt, retrieval/tool permissions, output schema, and maximum end-to-end latency.
3. **Budget matching:** run two comparisons:
   - fixed request-level token and latency caps
   - fixed dollar cap using current provider prices  
   Report actual input, output, cached, and tool tokens, requests, retries, p50/p95 latency, and failure rate.
4. **ToT ablation:** pre-register thought decomposition, candidate count, beam, vote count, evaluator prompt, pruning rule, maximum depth, and early-stop policy. Test `b=1` and a bounded wider beam to separate decomposition/evaluation benefit from raw sampling.
5. **Outcome evaluation:** use deterministic validators where possible. For subjective tasks, use blinded expert pairwise review with pre-specified rubric and inter-rater agreement. Keep model-as-judge separate from the final decision metric.
6. **Decision rule:** adopt only if ToT’s incremental validated quality or error-cost reduction exceeds its incremental total cost and meets latency/reliability limits, versus the best non-ToT arm at the same budget.

## Remaining gaps and stopping point

The original source does not provide current-model results, confidence intervals, per-case latency, full request counts, evaluator calibration, or a production-domain benchmark. It also does not establish a universal direct-versus-CoT-versus-ToT ranking. Research stopped because those questions exceed the requested original-paper-only scope.
