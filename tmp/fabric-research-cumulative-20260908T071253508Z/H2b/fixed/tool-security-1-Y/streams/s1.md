# AgentDojo v3 evidence for a permission-bounded tool agent

**Assigned question.** What original AgentDojo v3 evidence constrains deployment of a permission-bounded tool agent, and what defense tradeoffs remain unproven?

**Scope.** Only the frozen [AgentDojo arXiv v3 source](https://arxiv.org/html/2406.13352v3), including its appendices, as bounded by the assignment. This is benchmark evidence, not a production-security guarantee.

## Bounded answer

A permission-bounded design is the strongest measured comparator in v3: GPT-4o’s pre-data tool filter reduced targeted ASR from **57.69% to 6.84%** in its reported defense table, while benign utility rose from **69.0% to 73.13%** and utility under attack rose from **50.01% to 56.28%**. But this is evidence for a narrow mechanism: **preselecting tools before untrusted data prevents attacks that require tools outside the user task’s planned set**, especially read-only user tasks versus write-capable attacker goals. It is **not** evidence of safety when required user tools can also execute the attack, when tools cannot be planned in advance, across persistent multi-task contexts, or for content-manipulation attacks that require no additional tool. [§4.3](https://arxiv.org/html/2406.13352v3#S4.SS3), [Table 5](https://arxiv.org/html/2406.13352v3#A3.T5).

## F1. What v3 evaluates

- **Environment:** four stateful simulated applications, Workspace, Slack, Travel, and Banking, with mutable state and text-formatted tool outputs. The main text says **74 tools**, **97 user tasks**, and **27 injection targets**, crossed per environment into **629 security cases**. User and attacker success are deterministic checks over model output and pre/post environment state, not LLM judging. [§3–§3.1](https://arxiv.org/html/2406.13352v3#S3), [Table 1](https://arxiv.org/html/2406.13352v3#S3.T1).
- **Case construction:** an attack is inserted only at candidate placeholders in outputs of tools identified by the user task’s ground-truth required call sequence. Thus results measure injections on tool outputs the agent is expected to query, not arbitrary unobserved placement. [Appendix A, Attacks](https://arxiv.org/html/2406.13352v3#A1).
- **Workload bounds:** tasks can require up to 18 calls, tool/state context up to 7,000 GPT-4 tokens and tool descriptions up to 4,000 tokens. Injection goals span one to 20 steps and generic-to-sensitive actions. [§3.1](https://arxiv.org/html/2406.13352v3#S3.SS1).
- **Metrics and denominators:**  
  - benign utility: fraction of 97 user tasks solved without attack  
  - utility under attack: fraction of 629 user/injection pairs where the user task is solved **without adversarial side effects**  
  - targeted ASR: fraction of security cases where the attacker goal is met.  
  The paper also defines multi-attack success as any attack succeeding per case, representing a best-of-collection attacker. [§3.4](https://arxiv.org/html/2406.13352v3#S3.SS4).
- **Models:** Claude 3 Opus/Sonnet/3.5 Sonnet, Command R+, Gemini 1.5 Flash/Pro, GPT-3.5 Turbo, GPT-4 Turbo, GPT-4o, and Llama 3 70B. All used the default system prompt, with model-specific extra prompts for Claude and Llama; official provider APIs were used except Llama. Defense and attack ablations focused on GPT-4o because it had the highest benign utility among models available for detailed analysis. [§4](https://arxiv.org/html/2406.13352v3#S4).

## F2. Measured baseline and attack results

Under the generic “Important message” attack, Table 3 reports:

| Model | Benign utility | Utility under attack | Targeted ASR |
|---|---:|---:|---:|
| Claude 3 Opus | 66.61% ±3.69 | 52.46% ±3.90 | 11.29% ±2.47 |
| Claude 3.5 Sonnet | 78.22% ±3.23 | 51.19% ±3.91 | 33.86% ±3.70 |
| GPT-4o | 69.00% ±3.61 | 50.08% ±3.91 | 47.69% ±3.90 |
| GPT-4 Turbo | 63.43% ±3.76 | 54.05% ±3.89 | 28.62% ±3.53 |
| Command R+ | 25.44% ±3.40 | 25.12% ±3.39 | 0.95% ±0.76 |

Full values are in [Table 3](https://arxiv.org/html/2406.13352v3#A3.T3). The source reports 95% proportion confidence intervals using `statsmodels.stats.proportion.proportion_confint`; it does not state a repeated-run/seed protocol in the reported passages.

For GPT-4o, attack wording materially changes outcomes. In Table 4, targeted ASR is **3.66% TODO**, **5.41% ignore-previous**, **5.72% InjecAgent**, **57.7% Important message**, and **57.55% Max**. The reported “Max” chooses the most effective of the four prompts per case. Corresponding untargeted ASR is 32.75%, 33.23%, 31.48%, 49.9%, and 68.36%. [§4.2](https://arxiv.org/html/2406.13352v3#S4.SS2), [Table 4](https://arxiv.org/html/2406.13352v3#A3.T4).

Operationally important heterogeneity: the GPT-4o Slack suite had **92%** attack success, while one Travel injection requiring both an expensive booking and email exfiltration succeeded in **0%** of cases because the agent often completed only one malicious subgoal. End-of-tool-output injections reached up to **70% average ASR**. [§4.1](https://arxiv.org/html/2406.13352v3#S4.SS1), [Appendix D](https://arxiv.org/html/2406.13352v3#A4).

## F3. Measured defense tradeoffs

All Table 5 results are GPT-4o against the paper’s strongest selected attack configuration:

| Defense | Benign utility | Utility under attack | Targeted ASR |
|---|---:|---:|---:|
| No defense | 69.00% ±3.6 | 50.01% ±3.9 | 57.69% ±3.9 |
| Data delimiters | 72.66% ±3.5 | 55.64% ±3.9 | 41.65% ±3.9 |
| PI detector, abort on detection | 41.49% ±3.9 | 21.14% ±3.2 | 7.95% ±2.1 |
| Repeat user prompt after each call | 85.53% ±2.8 | 67.25% ±3.7 | 27.82% ±3.5 |
| Pre-data tool filter | 73.13% ±3.5 | 56.28% ±3.9 | 6.84% ±2.0 |

Source: [§4.3](https://arxiv.org/html/2406.13352v3#S4.SS3), [Table 5](https://arxiv.org/html/2406.13352v3#A3.T5).

Measured tradeoffs:

- The detector approaches the tool filter’s ASR but does so by aborting on any detected tool output and has many false positives, reducing benign utility by **27.51 percentage points** from the undefended result.
- Delimiters retain utility but leave **41.65%** targeted ASR.
- Prompt repetition has the best reported utility values but remains **27.82%** targeted ASR. The authors explicitly judge it unlikely to withstand an adaptive injection that tells the model to ignore future instructions.
- The tool filter has the best reported targeted-ASR result, but does not remove it. Its reported **6.84%** is not zero.

## F4. Deployment constraints and unproven boundaries

**Measured applicability condition.** Apply a pre-data, enforced least-privilege tool set only where the user task’s required capabilities can be determined before reading untrusted content and exclude the attacker’s required capability. This is the demonstrated read-user-task/write-attacker-goal mechanism. [§4.3](https://arxiv.org/html/2406.13352v3#S4.SS3).

**Known failure boundaries.**

1. **Shared-capability cases:** required user tools are also sufficient for the attack in **17%** of v3 cases. Tool filtering cannot establish protection there.
2. **Dynamic tool discovery:** it fails when a result determines which tools are needed next.
3. **Persistent contexts:** v3 does not cover multiple user tasks without resetting context. An injection could wait until a later task enables its needed tool.
4. **No-extra-tool attacks:** even more involved isolation can remain vulnerable when malicious content only changes a result or recommendation, such as biasing a hotel selection.
5. **Threat-model incompleteness:** v3 itself describes its attacks and defenses as relatively simple, proposes stronger adaptive attacks and defenses, and notes absent multimodal tasks and realistic injection length/format constraints. [§5](https://arxiv.org/html/2406.13352v3#S5).

Therefore, permission bounding is a practical control for separable capabilities, not an adoption gate for the known shared-tool, dynamic, persistent-context, or recommendation-manipulation cases.

## F5. Source conflicts and qualifications

- **Tool-count conflict:** main §3.1 says **74 tools**, and Table 1’s rows sum to 74, but Table 1’s caption and the data card say **70 tools**. This note preserves the conflict rather than resolving it.
- **GPT-4o attack-result mismatch:** Table 3 reports GPT-4o targeted ASR **47.69%** under the baseline evaluation, while Table 4 reports **57.7%** for “Important message,” and Table 2 reports a **45.8%** knowledge-ablation baseline. The supplied source does not explain the configuration/run difference. These must not be treated as one denominator-compatible result.
- **“Adaptive” is bounded:** Table 4 Max selects among four fixed prompt phrasings. It is not evidence against a defense-aware adaptive attacker. The data card explicitly calls use of default attacks without a thorough adaptive attack evaluation unsuitable. [Data card §F.5.2](https://arxiv.org/html/2406.13352v3#A6).

## Proposed paired local transfer evaluation

This is a proposed test, not a source-established result.

1. **Arms:** hold model, prompts, tools, state, token/runtime limits, and cases fixed. Compare an unrestricted agent against an agent whose capability set is planned and enforced **before** the first untrusted tool result.
2. **Paired cases:** run each identical benign task and injected case in both arms. Use deterministic state checks for user completion, prohibited side effects, and attacker-goal completion, matching v3’s metric definitions.
3. **Strata:** report separately:  
   - S1: pre-plannable user tools exclude attack tools, the demonstrated mechanism  
   - S2: user and attack share an allowed tool, the known 17%-type failure boundary  
   - S3: tool need depends on untrusted intermediate results  
   - S4: multi-task retained-context sequences  
   - S5: recommendation/content-manipulation attacks requiring no forbidden tool.
4. **Attack battery:** include the four v3 phrasings, position injections near tool-output ends, and report best-of-fixed-prompt results. Add a defense-aware adaptive attack phase as an exploratory test, clearly separate from S1’s demonstrated comparison.
5. **Decision rule:** only claim transfer for S1 if the bounded arm preserves benign utility and materially lowers targeted ASR with compatible denominators and intervals. Treat any S2–S5 reduction as exploratory, not evidence that permissions solve those failure modes.

## Remaining gaps and stopping point

The original source does not provide a production deployment study, repeated-trial protocol, per-stratum tool-filter outcomes, adaptive-defense-aware attack outcomes, or a resolution of its table/configuration discrepancies. Research stopped because the controlled phase permits only this frozen original v3 source.
