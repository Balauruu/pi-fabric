# T2 / R1 — Measured run-design interventions for coding agents

**Question owned.** What original evaluations isolate or materially test run-design choices while holding the underlying model and reasoning effort fixed? Scope is coding-agent context selection, tool feedback, validation/repair, retries, and decomposition, through **2026-09-07**. This is evidence for R1 only, not a cross-stream adoption decision.

## Bounded answer

The strongest direct evidence is not a universal agent ranking. It shows that, for fixed models on specific repair benchmarks:

1. **Context and tool-interface design can materially change success and cost.** SWE-agent’s fixed-GPT-4-Turbo ablations on 300 SWE-bench Lite tasks found 18.0% resolved for its interface versus 11.0% for a shell-only agent. Its context and editing-feedback components each had measurable effects.  
2. **Executable validation can improve candidate selection, but it costs resources and depends on a valid test signal.** Agentless’s fixed-GPT-4o selection ablation rose from 25.67% with majority vote to 27.00% with regression tests and 32.00% with generated reproduction tests on SWE-bench Lite, at an incremental $0.25 per task for reproduction testing.  
3. **Retries buy additional pass@k success at approximately proportional cost, not a demonstrated guarantee of correct selection.** AutoCodeRover’s three independent runs raised SWE-bench Lite resolution from 19% to 26%, raising average cost from $0.43 to $1.30.  
4. **Structured staged workflows are not automatically superior.** Agentless’s fixed, non-autonomous localization→repair→validation workflow reported 32% at $0.70 on SWE-bench Lite, but this is a multi-component comparison, not causal proof that removing agent autonomy causes the gain.  
5. **The evidence transfers only to benchmark-like bug fixing with runnable tests.** Leakage, test adequacy, evaluator dependence, and changing multiple harness variables constrain all claims.

## Source passages and interpretation

### F1. Context selection has a measurable interior optimum

SWE-agent’s Table 3 is a particularly useful controlled artifact because its model is held fixed and the variations are explicit. The best measured viewer setting was **100 lines**, while both **30 lines** and the **full file** reduced resolution. The authors also report that retaining only the last five observations beat full-history retention, **18.0% versus 15.0%**. [Table 3 and §5.1](https://arxiv.org/html/2405.15793#S5)

The governing condition is budgeted interaction. The study used a $4 per-instance cap and auto-submitted current edits when exceeded. It also notes that iterative result-by-result search led models to inspect every match, exhausting budget or context. This is evidence for **bounded, summarized, fresh context**, not evidence that five observations or 100 lines is production-optimal.

### F2. Tool feedback and guardrails help in the tested interface

SWE-agent’s editor without linting resolved **15.0%**, versus **18.0%** with its linting guardrail. Its no-edit alternative resolved **10.3%**. The paper’s mechanism is immediate, interpretable feedback after edits and prevention of major malformed edits. [§5.1](https://arxiv.org/html/2405.15793#S5.SS1)

This does not measure security. It measures benchmark functional resolution only.

### F3. Validation is useful when the validation signal is relevant

Agentless’s patch-selection ablation is the cleanest measured validation contrast recovered here. Generated reproduction tests increased resolved tasks by **15** over majority voting and **15** over regression-test-only filtering. The cost is not free: reproduction testing adds **$0.25** on average. [Table 4](https://arxiv.org/html/2407.01489#S5.SS2.SSS3)

Its reliability condition is explicit: only **213/300** generated reproduction tests emitted the expected reproduction message on the original repository, and the authors then checked tests against the ground-truth patch because a test that reproduces an issue can still be an incorrect specification. [§5.1.3](https://arxiv.org/html/2407.01489#S5.SS1.SSS3)

### F4. Retries improve opportunity, not necessarily decision quality

AutoCodeRover repeated complete runs three times. The Lite contrast is **57 to 78** solved tasks, at roughly three times model-token cost. [Table 2](https://arxiv.org/html/2404.05427#S6.T2) This establishes value in candidate diversity under its deterministic-low-temperature configuration. It does not show that three serial repair turns with test feedback have the same effect.

### F5. Decomposition evidence is presently package-level

Agentless provides important counterevidence to claims that a freely acting tool agent is necessary. However, its 32% result packages hierarchical localization, embedding retrieval, 40 patch samples, generated tests, a Search/Replace format, ranking, and a modified evaluation setup. It is not attributable to “decomposition” alone. [Method and protocol](https://arxiv.org/html/2407.01489#S3)

## Counterevidence and transfer limits

| Limit | Why it changes the inference |
|---|---|
| **L1: Multi-variable changes** | ACR-SBFL changes static-analysis hints, test validation, and retry behavior together. Agentless versus agentic baselines changes far more than decomposition. Do not convert either into a one-factor causal claim. |
| **L2: Benchmark leakage and task artifacts** | Agentless reports SWE-bench Lite issues containing exact ground-truth patches (**4.3%**), insufficient critical information (**10.0%**), or misleading solutions (**5.0%**). [Source](https://arxiv.org/html/2407.01489#S1) Closed-model training data are unavailable, so contamination cannot be excluded. |
| **L3: Test-based evaluation is not semantic correctness** | Passing tests defines SWE-bench resolution. RepairAgent distinguishes plausible from correct patches and uses developer-patch matching plus manual semantic consistency checks. [Method](https://arxiv.org/html/2403.17134#S5.SS1) Neither evaluator establishes all intended behavior. |
| **L4: Oracle test availability** | Defects4J provides a failing test. RepairAgent explicitly notes that real use may not. ACR-SBFL uses developer-written tests that a production report may lack. Validation benefits must be tested separately for cases with and without reliable failing tests. |
| **L5: Randomness and selection variance** | SWE-agent reports similar average resolution across six Lite runs but materially varying per-instance success. [Appendix B.5](https://arxiv.org/html/2405.15793#A2.SS5) Use paired instances and repeated seeds. |
| **L6: Cost definitions differ** | SWE-agent reports average cost over successfully resolved instances in its main table, while other papers report average task inference cost or multi-run total. Dollar amounts use historical model prices. Compare tokens, wall time, and per-task budget locally, not paper dollars. |
| **L7: Realistic localization can hurt** | RepairAgent’s switch to GZoltar localization reduced fixes from 21 to 16 in its n=100 ablation and raised cost 81%, because cycles were not increased. [Table VI and text](https://arxiv.org/html/2403.17134#S5.SS4) An intervention proven with oracle localization is not an adoption gate for noisy localization. |

## Concrete paired evaluation artifact

Use this artifact to test one run-design change without changing model, reasoning effort, system prompt, task split, or per-task resource ceiling.

```yaml
experiment: bounded_context_and_validation_v1
population:
  source: production-like, time-held-out bug/feature tasks
  unit: repository-task pair
  strata:
    - runnable_failure_signal: [yes, no]
    - change_scope: [single_file, multi_file]
    - repository_size: [small, medium, large]

fixed:
  model: "<exact production model ID>"
  reasoning_effort: "<fixed>"
  system_prompt: "<hash>"
  tool_permissions: "<identical allowlist>"
  base_commit_and_environment: "<container digest>"
  decoding_and_seed_schedule: "<identical paired schedule>"
  wall_clock_cap_minutes: 30
  token_cap: 120000
  candidate_cap: 1

arms:
  control:
    context: "current production selection"
    validation: "current production validation"
  treatment:
    context: "bounded retrieved snippets, deduplicated tool output, rolling recent-observation summary"
    validation: "run existing targeted checks; feed structured failure location, command, exit status, and bounded stderr once"
    repair: "one additional repair turn only after a new actionable validation failure"

pairing:
  - "Run both arms on every task and every seed."
  - "Randomize arm order."
  - "Freeze repository, dependencies, test command, timeout, and evaluator before runs."
  - "Record whether the treatment actually received a valid actionable failure signal."

outcomes:
  primary:
    - independently_verified_task_success
  secondary:
    - evaluator_pass_rate
    - regression_failures
    - wall_time
    - input_tokens
    - output_tokens
    - tool_calls
    - validation_runtime
    - cost_per_task
  diagnostic:
    - context_bytes_presented
    - truncation_events
    - repair_after_validation_count
    - repeated_action_count
    - failure_signal_quality

analysis:
  - "Report paired success difference with confidence interval."
  - "Report win/loss/tie and McNemar test."
  - "Report medians and p90 for time, tokens, and cost."
  - "Report strata separately. Do not pool runnable-signal and no-signal cases as one validation claim."
  - "Manually inspect all evaluator-pass but independently-failed cases."
```

## Evidence-to-test operational table

This is an R1 contribution, not an adoption decision.

| Run-design question | Source-established applicable mechanism | Local comparator | Required measurement |
|---|---|---|---|
| How much repository/tool output to retain? | Bounded context beat full history and full files in SWE-agent’s setting. | Current policy versus bounded summarized policy. | Verified success, tokens, truncation, repeated search, p90 time. |
| Should tool edits return structured feedback? | SWE-agent linting/edit feedback improved its interface result. | Existing edit feedback versus syntax/test-aware structured feedback. | Syntax failures, edit retries, verified success, tool-call count. |
| Should validation trigger one repair? | Validation improved Agentless selection where tests reproduced the task. | Same candidates with and without one validation-directed repair. | Success separately for valid and invalid/no failure signals. |
| Should whole runs be retried? | Three independent ACR runs increased pass@k at near-tripled token spend. | One run versus fixed N independent runs under equal aggregate budget. | Marginal success per extra run and marginal cost. |
| Should work be staged? | Agentless is a promising package-level counterexample to unrestricted autonomy, not an isolated causal result. | Existing loop versus staged loop with all other variables frozen. | Stage failure attribution, success, total tool calls, cost. |

## Remaining gaps and stopping point

- No recovered primary experiment cleanly isolates **decomposition alone** from retrieval, candidate count, validation, and scheduling.
- No recovered primary experiment cleanly isolates **feedback-directed serial repair** from independent retry sampling on a modern repository benchmark.
- No source establishes an optimal global retry count, context size, validation suite, or tool set.
- No source supports security, safety, or universal model-ranking claims.
- Research stopped after original papers repeatedly supported the same bounded conclusions and further search access was rate-limited. The Self-Debugging paper’s original HTML/PDF was retrievable only as an oversized response, so no quantitative claim from it is retained.
