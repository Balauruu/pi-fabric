## R4: exact fixed-model paired evaluation that could change the recommendation

### Design

1. Build a representative task set before inspecting outcomes. Stratify by repository navigation, implementation, tests, debugging, and tool/interface failures.
2. For each task compare baseline against **one** intervention only, in identical fresh repository states. Randomize condition order within task.
3. Pin and record: exact Terra model snapshot, medium reasoning effort, system/task contract, tool definitions and permissions, environment image, repository commit, harness, timeout, context/action/retry budgets, evaluator, and hidden tests.
4. Use three repetitions per task-condition as an initial screen. A 24-task screening set is 144 terminal runs. This count is a proposed screening design, not a claim of statistical sufficiency.
5. Count every terminal run: accepted, evaluator-rejected, test/build failure, tool/interface failure, timeout, agent-aborted, environment-invalid, evaluator-invalid. Rerun an invalid pair only when the same external fault invalidates both members, and report invalid counts separately.

### Measures

- Accepted-task rate with paired, task-clustered uncertainty.
- Accepted-task quality from independent acceptance evaluation and hidden tests, separately from raw test pass.
- Wall time from start to terminal state for every run, plus accepted runs separately.
- Failure-category shift, retries, loops, token/tool cost, and out-of-scope work.

### Pre-register decision rules

Choose harm and adoption thresholds before execution based on operational tolerance. The following are **provisional examples from the counterevidence stream, not evidence-derived values**: narrowly adopt only if the lower 95% confidence bound of accepted-task-rate difference is at least +5 percentage points, no failure category rises by 3 points or more, and median accepted-run wall-time ratio is at most 1.15. Reject/default-off if the upper bound is at most 0, accepted-task rate drops by 3 points or more, or median all-run wall time rises by more than 25%. Otherwise expand only the affected stratum.

### Usable checklist

- [ ] Exact Terra snapshot and `medium` reasoning effort captured.
- [ ] One causal mechanism changes per paired comparison.
- [ ] Fresh identical task states and randomized order.
- [ ] Context, action, retry, timeout, tools, permissions, prompt, and evaluator pinned.
- [ ] Hidden-test and independent acceptance outcomes retained.
- [ ] All terminal states and invalid-run reasons counted.
- [ ] Wall time measured on every run.
- [ ] Paired uncertainty and per-stratum results reported.
- [ ] Stop/revert rule set before outcomes are inspected.
- [ ] Adoption restricted to passing strata.

## What would overturn this result

Expose callable `pi-web-access` actions, then collect direct primary-source evidence and rerun the existing independent assignments. A valid future recommendation additionally requires the paired Terra evaluation above to show its pre-registered acceptance, wall-time, and failure-accounting criteria under the exact intended harness.
