# Counterevidence-transfer

**Decision:** do not select a production prompt, example set, CoT scaffold, retry policy, or tool/context design from a single benchmark or model result. Treat each as a versioned configuration requiring held-out task, format, context-position, and cost tests.

## Decisive evidence

| ID | Original source, method, and result | Transfer limit / production implication |
|---|---|---|
| F1 | Few-shot demonstrations: Min et al. found that randomly replacing demonstration labels “barely” hurt performance across classification and multiple-choice tasks in **12 models including GPT-3**. Label space, input distribution, and sequence format, rather than semantic correctness of example labels, drove much of the result. Example count and exact model versions vary by experiment. [Min et al., 2022](https://arxiv.org/abs/2202.12837) | A successful example set may be formatting/label-space conditioning, not transferable task learning. Do not infer that “better examples” are causally responsible without label-randomization and format controls. **R2: examples, task/model transfer.** |
| F2 | Format-only few-shot changes produced up to **76 accuracy-point** differences for **LLaMA-2-13B**; increasing size, example count, or instruction tuning did not eliminate sensitivity. Format quality correlated only weakly across models. [Sclar et al., 2024](https://arxiv.org/abs/2310.11324) | A prompt chosen on one model is not a portable model comparison or deployment default. Evaluate a bounded distribution of semantically equivalent formats on the exact production model/version. **R2: prompt regressions and model transfer.** |
| F3 | CoT’s positive result is conditional: eight CoT exemplars with **PaLM 540B** achieved state-of-the-art GSM8K accuracy, and the authors frame the behavior as emerging in “sufficiently large” models. The study spans arithmetic, commonsense, and symbolic tasks, not arbitrary production work. [Wei et al., 2022/2023](https://arxiv.org/abs/2201.11903) | This is evidence for a particular large-model, few-shot reasoning regime, not for universal “think step by step.” Test against direct answering by task and model. **R2: reasoning and model/task transfer.** |
| F4 | CoT explanations can rationalize biased answers. With few-shot multiple-choice option-order bias, **GPT-3.5** and **Claude 1.0** often omitted the bias from their explanations; bias toward wrong answers reduced accuracy by up to **36 percentage points** over **13 BIG-Bench Hard tasks**. [Turpin et al., 2023](https://arxiv.org/abs/2305.04388) | A plausible reasoning trace is not evidence of causal reasoning or an adequate correctness check. Evaluate final outcomes independently and do not use CoT as an audit trail. **R2: reasoning regressions.** |
| F5 | Self-consistency samples multiple reasoning paths and votes by marginalization. It reported gains over greedy CoT of **+17.9 GSM8K, +11.0 SVAMP, +12.2 AQuA, +6.4 StrategyQA, +3.9 ARC-Challenge**. [Wang et al., 2023](https://arxiv.org/abs/2203.11171) | The gain is an inference-time ensemble, not a free prompt improvement. Its cost is multiple full reasoning completions plus aggregation. The inspected primary summary does not specify a universal sample/retry budget, so pricing and latency must be measured on the deployed model. **R2: retries, reasoning-cost transfer.** |
| F6 | In multi-document QA and key-value retrieval, moving the relevant information within the same long input caused large position effects: performance was typically highest at the beginning/end and worse in the middle, including on long-context models. [Liu et al., 2023](https://arxiv.org/abs/2307.03172) | Context-window fit is not usable-context proof. Hold total tokens fixed and test relevant-evidence position, distractor load, and ordering before adding examples, tool output, or retrieved documents. **R2: context transfer/regressions.** |
| F7 | Toolformer’s favorable result is narrow: it trains a model to decide when/how to call specified APIs after a handful of demonstrations per API, with calculator, QA, search, translation, and calendar tools, then reports improved zero-shot downstream performance. [Schick et al., 2023](https://arxiv.org/abs/2302.04761) | It does not establish that an untrained production model will reliably use a new tool schema from prompt examples alone. The intervention includes tool-use training and a fixed tool family. **R2: tool-scaffold transfer.** |
| F8 | Stateful, multi-turn tool use remains difficult: ToolSandbox specifically tests implicit state dependencies, canonicalization, insufficient information, dynamic intermediate/final milestones, and on-policy conversation, finding these hard even for leading models. [Lu et al., 2024](https://arxiv.org/abs/2408.04682) | Single-turn JSON/function-call scores do not transfer to stateful workflows. Evaluate asking, refusal, state mutation, recovery, and outcome verification separately. **R2: tool-use transfer.** |
| F9 | At larger tool scales, MCPVerse exposes **550+ executable tools** and an action-space description exceeding **140k tokens**. Most evaluated models degraded with larger tool sets, while some agentic models benefited from expanded exploration. [Lei et al., 2025](https://arxiv.org/abs/2508.16260) | Tool availability, tool-description budget, and tool-selection/retrieval policy are coupled. “More tools in context” is not a monotonic improvement. **R2: tool/context budget limits.** |

## Counterevidence to overgeneralizing sensitivity

F10. Prompt instability is not necessarily irreducible model behavior. A later study attributes a substantial portion of observed classification sensitivity to **underspecified prompts** and finds specific instructions reduce variance, although internal representations change only marginally. This is useful counterevidence to “all prompt wording is inherently unstable,” but it is a 2026 preprint and does not negate F2’s controlled format sensitivity. [Pecher et al., 2026](https://arxiv.org/abs/2602.04297)

## Operational selection rule

1. **Lock the deployment tuple:** provider/model revision, temperature/seed policy, system prompt, tool schemas, retrieval policy, max context, output cap, retry/sample count, and evaluator version.
2. **Require matched comparators:** direct answer vs CoT, zero-shot vs examples, greedy vs retry/ensemble, compact retrieval vs expanded context, and retrieved-tool subset vs full tool list.
3. **Measure:** task success, constraint/tool-call validity, unsupported-claim rate, p50/p95 latency, input/output/tool tokens, retry rate, and cost per successful task.
4. **Stress transfer:** hold out task families, paraphrase/format variants, example-label randomization where applicable, middle-context placement, distractor tools, state changes, and model-version upgrades.
5. **Promote only robust deltas:** require improvement across the planned production slice and no unacceptable regression in the stress slice. Preserve confidence intervals or repeated-run variation where stochasticity applies.

## R2 coverage and gaps

- **Covered:** original counterevidence for few-shot examples, prompt-format regressions, CoT faithfulness failure, retry-cost trade-off, long-context position failure, and stateful/large-tool transfer limits.
- **Partial:** replication. The sources provide independent studies across different models and tasks, but this review found no single fully matched, multi-provider replication of the same prompt/scaffold intervention with shared budgets.
- **Missing for a production decision:** exact vendor model revisions, decoding settings, tool schemas, token pricing, latency, retriever behavior, domain-specific task distribution, and evaluator reliability. Tool benchmarks also do not substitute for production outcome verification.
- **Stop reason:** coverage saturated across the decision-changing intervention classes requested. Additional retrieved sources largely introduced new benchmarks or reported aggregate agent scores without a more controlled counterexample than F1–F9.
