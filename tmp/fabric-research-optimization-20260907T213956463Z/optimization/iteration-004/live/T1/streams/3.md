## Findings

### F1. Evaluate retrieval, invocation, and multi-step planning as separate gates

[API-Bank](https://arxiv.org/html/2304.08244) defines three progressively harder conditions: **Call** with known APIs, **Retrieve+Call** for an unknown single API, and **Plan+Retrieve+Call** for unknown multi-API work. Its executable evaluation used **73 APIs**, **314 manually annotated dialogues**, and **753 calls**. API correctness meant equivalent database effects and returned results, not merely syntactic function-call matching.

**Material evidence unit — call-stage degradation**
- **Source / locator:** [API-Bank, Table 3 and §§2.1, 3.3, 5](https://arxiv.org/html/2304.08244)
- **Claim:** Tool correctness falls sharply as retrieval and planning are added.
- **Result:** GPT-4 (`gpt-4-0613`) API-call correctness: **63.66% Call**, **37.04% Retrieve+Call**, **70.00% Plan+Retrieve+Call**, **60.24% total**. GPT-3.5-turbo: **59.40%**, **38.52%**, **22.00%**, **47.16%**, respectively.
- **Method / comparator:** Execution-equivalence accuracy on frozen API-Bank state. The three conditions differ in whether APIs are known and whether a multi-call plan is required.
- **Caveat:** Only 50 evaluation instances each for Retrieve+Call and Plan+Retrieve+Call. API-Bank uses simulated, fixed-response APIs, not live production dependencies.
- **Decision dimension:** Tool-stage correctness and agent routing.
- **Source-unique in this assignment:** Yes.

**Operational implication:** Report a separate denominator and pass rate for tool retrieval, schema-valid invocation, execution-equivalent effect, and task completion. A single “agent success” number hides the failure boundary.

### F2. Tool retrieval is a material bottleneck at realistic catalog scale

[ToolRet](https://arxiv.org/html/2503.01763) evaluates retrieval before calling across **7,615 tasks** and **43,215 tools**: 36,978 web APIs, 3,794 code functions, and 2,443 custom applications. The source reports an average **2.17 target tools per query** and query-to-target ROUGE-L of **0.06**, versus 0.31 for Natural Questions.

**Material evidence unit — retrieval quality**
- **Source / locator:** [ToolRet, Tables 1–2 and §6](https://arxiv.org/html/2503.01763)
- **Claim:** Strong general-purpose retrievers remain incomplete at large tool-corpus retrieval.
- **Result:** Best reported base model, NV-Embed-v1, achieved **nDCG@10 33.83** and **Completeness@10 32.12** averaged across ToolRet subsets.
- **Method / comparator:** Retrieval against 43,215 tools. Completeness@10 requires all required tools in the top 10, unlike ordinary relevance metrics.
- **Caveat:** The corpus aggregates 34 prior datasets. The authors identify a one-to-many labeling risk where functionally similar tools may be valid but unlabelled.
- **Decision dimension:** Whether to invest in retrieval/reranking before modifying the calling prompt.
- **Source-unique in this assignment:** Yes.

**Material evidence unit — retrieval affects end-to-end pass rate**
- **Source / locator:** [ToolRet, §7.1 and Figure 5](https://arxiv.org/html/2503.01763)
- **Claim:** Replacing a curated toolset with retrieved tools lowers agent pass rate.
- **Result:** The paper reports ToolLlama pass rate **50.60** when using tools retrieved by `bge-large`, a **11.40-point decrease** from its annotated-toolset condition.
- **Method / comparator:** ToolBench experiment replacing the official annotated candidate set with a retriever’s outputs.
- **Caveat:** This is a ToolBench-specific, retrieval-then-calling setup, not evidence that the same decrement transfers to another model, tool catalog, or dynamic interleaved retrieval.
- **Decision dimension:** Retrieval quality is an independently testable prerequisite for calling quality.
- **Source-unique in this assignment:** Yes.

### F3. ReAct improves interactive outcomes in some environments, not universally

[ReAct](https://arxiv.org/html/2210.03629) interleaves thought, action, and observation using PaLM-540B with few-shot trajectories. On question-only HotpotQA and FEVER, it used a limited Wikipedia API with `search`, `lookup`, and `finish`; on ALFWorld and WebShop, actions were environment interactions.

**Material evidence unit — interactive-agent benefit**
- **Source / locator:** [ReAct, §4, Tables 3–4](https://arxiv.org/html/2210.03629)
- **Claim:** Sparse reasoning traces improved tool/environment interaction in the study’s interactive benchmarks.
- **Result:** ALFWorld best-of-six success was **71% ReAct** versus **45% Act** and **37% BUTLER**. WebShop success was **40.0% ReAct** versus **30.1% Act**, while score was **66.6** versus **62.3**.
- **Method / comparator:** ALFWorld: 134 unseen games, six prompts per task type built from permutations of two of three manually annotated trajectories. WebShop: 500 test instructions. Act used the same trajectories with thoughts removed.
- **Caveat:** Best-of-six is not an average deployment outcome. Environments are simulations. WebShop expert-human success was **59.6%**, leaving a 19.6-point gap.
- **Decision dimension:** Use agent reasoning only where state tracking, noisy observations, or tool-mediated information is necessary.
- **Source-unique in this assignment:** Yes.

**Material evidence unit — ReAct counterexample**
- **Source / locator:** [ReAct, Table 1 and §3.3](https://arxiv.org/html/2210.03629)
- **Claim:** ReAct is not a universal replacement for CoT.
- **Result:** On PaLM-540B, question-only HotpotQA exact match was **27.4 ReAct** versus **29.4 CoT** and **33.4 CoT-SC**. On FEVER accuracy it was **60.9 ReAct** versus **56.3 CoT** and **60.4 CoT-SC**.
- **Method / comparator:** Few-shot prompts. ReAct’s Wikipedia interface was deliberately limited to exact-page search and lookup. CoT-SC sampled 21 trajectories at temperature 0.7.
- **Caveat:** The hybrid fallback methods scored higher: **35.1 EM** for ReAct→CoT-SC on HotpotQA and **64.6%** for CoT-SC→ReAct on FEVER. This is evidence for conditional routing, not for ReAct alone.
- **Decision dimension:** Task-dependent adoption and fallback policy.
- **Source-unique in this assignment:** Yes.

### F4. ReAct has documented failure modes but no measured production cost in the primary study

ReAct set a maximum of **7 steps** for HotpotQA and **5** for FEVER because additional steps did not improve its reported performance. In a human review of sampled HotpotQA trajectories, ReAct failure categories were **47% reasoning error**, **23% unsuccessful search result**, **0% hallucination**, and **29% label ambiguity**. CoT failure categories included **56% hallucination** and **16% reasoning error**. These percentages are within each method’s sampled failures, not benchmark-level rates.

The paper reports no average calls, tokens, latency, dollar cost, or cost-per-success. Its conclusion says complex large-action-space tasks need more demonstrations, which can exceed the in-context input limit.

**Operational implication:** Treat ReAct’s repeated model-and-tool loop as an explicit cost hypothesis to measure locally, not as a sourced cost claim.

### F5. Call-stage policy can be brittle even after tool-use training

[Toolformer](https://arxiv.org/html/2302.04761) fine-tuned GPT-J 6.7B on self-generated and loss-filtered API calls, then evaluated zero-shot tool use. At inference, it limited decoding to **at most one API call per input** to avoid looping.

**Material evidence unit — call trigger sensitivity**
- **Source / locator:** [Toolformer, §5 “Decoding Strategy” and §7 “Limitations”](https://arxiv.org/html/2302.04761)
- **Claim:** Call selection depends on decoding policy and prompt wording.
- **Result:** For T-REx and WebQS, increasing the API-token top-*k* from 1 to 10 increased API-call rates from **40.3% / 8.5%** to **98.1% / 100%**, respectively. The source says calibration observed at *k*=1 was lost at higher *k*.
- **Method / comparator:** Same Toolformer model, different threshold rule for generating the API token.
- **Caveat:** This is a trained GPT-J 6.7B system, not a general result for current instruction-following models. The paper also reports inability to chain or interactively refine tool calls and sensitivity to exact input wording.
- **Decision dimension:** Tune call thresholds and tool-choice prompts against overcalling as well as task success.
- **Source-unique in this assignment:** Yes.

## Operational decision table

| Condition | Default technique | Measure before adoption | Failure signal | Paired alternative |
|---|---|---|---|---|
| Small, known tool set and one call | Structured call prompt with schema validation | Invocation-equivalent accuracy | Wrong name, argument, or state effect | Direct answer or deterministic router |
| Large or changing catalog | Retrieve then present a bounded candidate set | Recall@*k*, Completeness@*k*, then call accuracy | Required tool absent from candidates | Better retriever/reranker, catalog metadata |
| Multi-tool or stateful workflow | ReAct-like thought/action loop with explicit stop and fallback | Per-stage success, calls, tokens, latency, cost per completed task | Repetition, no-progress observations, exhausted budget | Plan-first or deterministic workflow |
| Closed-world reasoning with no external state need | CoT or direct response | Answer quality and token cost | Retrieval adds no quality gain | ReAct only for retrieval-needed cases |
| Weak, unstable, or high-stakes tool execution | Constrained calls plus execution verification | Safe-effect accuracy and recovery rate | Schema-valid but wrong effect | Human approval or deterministic executor |

## Counterevidence and limitations

- **ReAct transfer limit:** Its results use PaLM-540B, hand-authored few-shot trajectories, a limited Wikipedia API, and simulated environments. They do not establish efficacy for current models, proprietary APIs, or irreversible production tools.
- **No cost result:** Neither ReAct’s reported tables nor the inspected ToolRet/API-Bank studies establish a universal token, latency, or dollar premium for agent reasoning.
- **Retrieval labels are imperfect:** ToolRet’s cross-dataset aggregation can penalize functionally acceptable alternatives not marked as the original target.
- **Call correctness is not business correctness:** API-Bank tests execution equivalence in a fixed system. Production tests must include authorization, side effects, changing tool versions, and user-visible outcome quality.
- **Benchmark incompatibility:** API-Bank correctness percentages, ToolRet retrieval metrics, and ReAct environment success rates measure different systems and cannot be placed on one leaderboard.
