## Findings

### Material evidence unit M1: ToolBench-X measures recoverable tool-environment faults

[ToolBench-X paper](https://arxiv.org/html/2606.25819v1), “Reliability Hazard Injection,” Table 1, Table 2, Figure 4, Appendix C.

- **Environment and method:** 1,106 executable, deterministic multi-step tasks, 4,956 tools, seven domains, with sequential, parallel, and mixed workflows. Ground truth remains the clean-path answer. Evaluation permits 10 rounds per task, one call/retry/fallback/finish per round, 8,192 output-token cap, 120-second request timeout, and API retries up to three times with 2–10 second exponential backoff.
- **Injected hazards:**  
  1. Specification Drift  
  2. Invocation Error  
  3. Execution Failure  
  4. Output Drift  
  5. Cross-source Conflict  
  Each instance retains at least one valid recovery path. Execution Failure specifically includes timeouts, connection errors, runtime exceptions, and parsing failures, with bounded retry or fallback expected.
- **Metric:** final-task accuracy. A task is correct when the recorded backend state matches ground truth or the final response contains the ground-truth answer.
- **Outcome:** across 12 tested models, hazard-setting overall accuracy was 0.212–0.513. Best reported model, Doubao-Seed-2.0-Lite, scored **0.513** overall. GPT-5.4 scored **0.453**. Invocation hazards were comparatively easier, while execution and cross-source hazards were substantially harder for most models.
- **Decision dimension:** fault recovery.
- **Source-unique:** yes.

### Material evidence unit M2: Diagnosis hints outperform extra unguided retries

[ToolBench-X paper](https://arxiv.org/html/2606.25819v1), “Are failures unrecoverable, or merely undiagnosed?”, “Diagnosis is the dominant bottleneck,” Figure 4, Table 16.

- **Comparator:** distribution-preserving 200-task subset. Baseline is the injected-hazard, no-hint environment. Oracle is the same task in the clean environment. Hint provides a brief explanation of the tool anomaly only after failure. Test-time scaling reruns after failure without a hint, granting 10 additional interaction rounds.
- **Outcome:** targeted hints added **25.5–35.5 percentage points** over no-hint baseline and recovered approximately **60–80%** of baseline-to-oracle lost accuracy across five models. Test-time scaling added only **3.5–11.5 points**. Hints exceeded scaling by **24–32 points**.
- **Exact reported values:** GPT-5.4-Mini: **0.840** with hint versus **0.520** with test-time scaling. Claude-Sonnet-4.6: **0.775** with hint versus **0.535** scaling.
- **Interpretation:** the evidence supports structured fault diagnosis as a stronger recovery intervention than merely expanding reasoning/action budget in this injected-hazard setting.
- **Applicability limit:** these are post-failure interventions on 200 benchmark tasks, not evidence that externally supplied “hints” are safe or that unlimited retries help production systems.
- **Decision dimension:** recovery-policy design.
- **Source-unique:** yes.

### Material evidence unit M3: ToolSandbox evaluates stateful recovery, not security enforcement

[ToolSandbox paper](https://arxiv.org/html/2408.04682), §2.1–2.3, Table 4, Table 5, §7.

- **Environment:** 1,032 human-authored scenarios, 34 tools in 11 domains, average **13.9 turns** and **3.80 tool calls**. Forty-four percent of tools are stateful. A GPT-4o user simulator supports on-policy dialogue.
- **Fault/recovery probe:** calling `send_message` with cellular service off raises `ConnectionError`; the intended recovery is `set_cellular_service`, state update recognition, then retrying `send_message` (§2.1, Figure 1). Nested dependencies require disabling low-battery mode before enabling connectivity. Tool exceptions are captured through `stderr`; dependent calls made in parallel can incur deliberately injected race failures (Appendix A.6).
- **Metric:** average trajectory similarity over milestone-DAG matches. A minefield violation forces total score to zero: `score = score_M+ × I(score_M− = 0)`.
- **Outcome:** GPT-4o-2024-05-13 scored **73.0** overall, including **84.0** on State Dependency and **42.0** on Insufficient Information. Claude-3-Opus scored **69.2** overall. Best reported open model, Hermes-2-Pro-Mistral-7B, scored **31.4**.
- **Decision dimension:** state tracking, error-driven remediation, and unsafe hallucinated action detection.
- **Source-unique:** yes.

### Material evidence unit M4: AgentDojo supplies a security-specific tool-agent boundary

[AgentDojo paper](https://arxiv.org/html/2406.13352), §3.1, §3.4, §4, Tables 1–5.

- **Environment:** four mutable-state environments, Workspace, Slack, Travel, Banking. The paper inconsistently reports **70 tools** in Table 1 and **74 tools** in §3.1. It evaluates **97 user tasks**, **27 injection targets**, and **629 user-task/injection pairs**.
- **Method and metrics:** deterministic state-based utility and security functions rather than LLM grading. Benign utility is user-task success without attack. Utility under attack requires user success without adversarial side effects. Targeted attack success rate is the fraction where attacker goal is achieved.
- **Comparator:** ten agents, including GPT-4o, Claude 3/3.5, Gemini, GPT-4 Turbo, Llama 3 70B. GPT-4o defense comparison: no defense, delimiting, prompt-injection detector, repeat prompt, and tool filter.
- **Outcome:** under the “Important message” injection, GPT-4o had benign utility **69.00% ±3.61**, utility under attack **50.08% ±3.91**, and targeted ASR **47.69% ±3.90**. In the defense comparison, tool filtering produced benign utility **73.13% ±3.5**, utility under attack **56.28% ±3.9**, targeted ASR **6.84% ±2.0**. The detector reduced ASR to **7.95% ±2.1** but benign utility to **41.49% ±3.9**.
- **Decision dimension:** prompt injection and adversarial tool-use risk.
- **Source-unique:** yes.

## Decision table

| Deployment question | Evidence-supported conclusion | Control |
|---|---|---|
| Can nominal tool success establish recovery reliability? | No. ToolBench-X’s no-hint hazard accuracy remains at or below 0.513 across its tested models. | Measure clean, injected-hazard, and recovery performance separately. Report denominators and hazard type. |
| Are retries sufficient? | No. Extra 10-round test-time scaling was much weaker than anomaly-specific hints. | Use bounded retries with error-classification, fallback, idempotency, and explicit stop/escalation rules. |
| Does stateful task success establish authorization safety? | No. ToolSandbox explicitly does not address mandatory confirmation or authentication. | Enforce authorization, confirmation, least privilege, and transaction constraints outside the model. |
| Does a prompt-injection benchmark prove production security? | No. AgentDojo tests a bounded set of text-only attacks, environments, and task pairs. | Test adaptive attacks against the actual tools, data formats, privileges, and persistent context. |
| Should model-scored safety be accepted without verification? | No. ToolEmu’s automatic safety evaluator had 73.1% recall for safety failures. | Use deterministic state/action policies for high-impact operations and review residual failures. |

## Counterevidence and transfer limits

- **ToolBench-X:** hazards are deliberately recoverable and tools are deterministic. Its result does not estimate behavior under irrecoverable outages, side-effecting retries, adversarial tool outputs, live APIs, or authorization errors. Hint results depend on a trusted, post-failure anomaly explanation.
- **ToolSandbox:** GPT-4o user-simulator failures remained non-negligible. With knowledge-boundary plus demonstration prompting, hallucination was **6.97%** and instruction-following error **0.77%** in 1,032 annotated trajectories. Its four-run total simulator error was **8.02% ±1.36%**, **7.78% ±0.52%**, and **8.07% ±1.03%** across three agents. Milestones do not measure efficiency, and any minefield match zeros the full score.
- **ToolSandbox security gap:** mandatory confirmation and authentication are explicitly “currently not addressed” (§7). It is evidence for stateful recovery, not security certification.
- **AgentDojo:** attacks and defenses are relatively simple, lacks multi-task persistent-context and multimodal cases, and requires manual task/utility specification. Tool filtering can fail when required task tools also enable the attack, reported for **17%** of cases.
- **ToolEmu:** [ToolEmu](https://arxiv.org/html/2309.15817) shows why LM-emulated environments are useful but insufficient for security proof. Its safety evaluator had **75.3% precision** and **73.1% recall** for safety failures, and adversarial emulation reduced critical-issue-free simulations from **91.9% ±2.7%** to **85.6% ±3.6%**. This is counterevidence to treating emulator or LLM-judge results as ground truth.

## Smallest resolving evaluation

Run the deployed agent in a stateful replica of its highest-impact workflow with deterministic state/action oracles:

1. Select 30 representative tasks, including irreversible and permission-sensitive actions.
2. For each, run clean, one of the five ToolBench-X hazard classes, state-dependency failure, and untrusted-output injection conditions.
3. Compare no-recovery, bounded classify-and-recover, and human-escalation policies under identical action and time budgets.
4. Record task success, hazardous action rate, recovery success conditional on fault, duplicate-side-effect rate, escalation rate, and authorization-policy violations.
5. Require zero authorization-policy violations in the test set before widening tool privileges. Do not convert this threshold into a general security claim.
