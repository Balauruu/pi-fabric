## Actionable issues

1. **Discovery-planner ownership is contradictory and lacks a valid persisted plan owner.**
   - Evidence: [SKILL.md:45](/home/balauru/.pi-profiles/fabric/skills/fabric-research/SKILL.md#L45) makes the planner the first writer of `RESEARCH.md`; [SKILL.md:57](/home/balauru/.pi-profiles/fabric/skills/fabric-research/SKILL.md#L57) requires a discovery worker to produce the plan. But the mandatory discovery-worker contract at [references/stream-contracts.md:7](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/stream-contracts.md#L7) says a researcher must not edit `RESEARCH.md`, and only writes its unique stream. The phase text says it may save discoveries in “its own stream” without requiring Main to reserve and pass such a path first.
   - Failure boundary: a compliant discovery worker either cannot persist the assignment index where the ownership table requires it, or violates its required contract. Implementations will likely improvise Main-side plan writing or permit the planner to write `RESEARCH.md`.
   - Action: explicitly designate one planner output path and one planner write authority, with a no-write variant; make the parent and the stream contract agree.

2. **The no-write route remains impossible for its required workers.**
   - Evidence: [SKILL.md:51](/home/balauru/.pi-profiles/fabric/skills/fabric-research/SKILL.md#L51) removes write/edit grants and skips dossier creation. Yet [references/stream-contracts.md:46](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/stream-contracts.md#L46) unconditionally requires a researcher to create and incrementally update an owned document before retrieval; [references/synthesis-and-reporting.md:79](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/synthesis-and-reporting.md#L79) requires the substantive answer in `REPORT.md`; and [references/synthesis-and-reporting.md:98](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/synthesis-and-reporting.md#L98) requires validation to record in `RESEARCH.md` before its late no-write sentence. The last30days contract has the same ordering at [references/last30days.md:19](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/last30days.md#L19).
   - Failure boundary: a no-write worker must either disobey the no-write request, fail before retrieval, or return an ad hoc handoff that later roles were told is insufficient. The inline final exception does not replace the missing in-memory evidence/report/validation contracts.
   - Action: make no-write a first-class branch in each role reference before any mandatory file operation, with bounded in-program evidence and acceptance handoffs.

3. **The required-model preflight names the wrong catalog for an exact-key test.**
   - Evidence: [references/runtime.md:24](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/runtime.md#L24) requires testing `openai-codex/gpt-5.6-terra` in `tools.models()`. Runtime probe observed that catalog exposes `gpt-5.6-terra`, not the provider-qualified key; `agents.models({runner:"pi"})` exposes the required `.key`.
   - Failure boundary: a literal membership test against `tools.models()` falsely blocks the currently available required model. This directly breaks the required-model-absent branch in the opposite direction.
   - Action: use `agents.models({ runner: "pi" })` and compare `.key`, or specify an explicit, tested normalization rule.

4. **Single-writer and anti-race claims are instruction-only, not enforced at the write boundary.**
   - Evidence: [references/runtime.md:20](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/runtime.md#L20) acknowledges that tool allowlists and `cwd` are not filesystem sandboxes. [references/runtime.md:26](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/runtime.md#L26) grants workers unrestricted core `write`/`edit` names, while [references/runtime.md:30](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/runtime.md#L30) nevertheless requires exclusive document/state ownership and no state races. The worker prohibition at [references/stream-contracts.md:7](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/stream-contracts.md#L7) is only prompt policy.
   - Failure boundary: a mistaken or noncompliant worker can write any accessible absolute path, including a sibling stream or `state.json`; concurrent read-modify-write damage can occur before the coordinator detects it. The guidance should not present path ownership as a hard guarantee.
   - Action: either add actual isolation/path-constrained writing, or explicitly treat ownership as best-effort and validate/recover artifacts after every terminal worker before transfer. Do not claim race-free execution merely from prompts and a tool allowlist.

## Static boundary answers

- **Main corpus, gap repair, verification, report writing:** No unintended substantive leak is instructed. The skill expressly prohibits Main from retrieving during worker execution, rereading the corpus, repairing, or writing the report ([SKILL.md:16](/home/balauru/.pi-profiles/fabric/skills/fabric-research/SKILL.md#L16)); recovery is bounded and Main does not reconstruct research ([references/runtime.md:34](/home/balauru/.pi-profiles/fabric/skills/fabric-research/references/runtime.md#L34)). The narrow lookup is the stated exception.
- **Race writes:** Code-held `state.json` serialization is specified, but issue 4 leaves worker-document/state ownership unenforced. Therefore race-free operation is not proven.
- **False completion:** The written workflow correctly requires independent validation and partial status on failed checks ([SKILL.md:62](/home/balauru/.pi-profiles/fabric/skills/fabric-research/SKILL.md#L62)); no direct false-complete instruction was found. Indeterminate launches are explicitly non-complete. The no-write contradiction and untrusted write boundary can still prevent that policy from being reliably realized.
